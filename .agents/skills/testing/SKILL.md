# Testing

## Procedure

1. Inspect existing test framework, scripts, fixtures, and CI conventions.
2. Map acceptance criteria and changed behavior to test cases.
3. Choose appropriate layers: unit, component, integration, API, contract, regression, or end-to-end.
4. Include relevant boundary, negative, permission, and failure-path tests.
5. Run focused tests first, then broader suites at quality gates.
6. Diagnose failures; distinguish product defects, test defects, and environment issues.
7. Record commands, environment, counts/results, and limitations.
8. Do not weaken assertions or delete tests merely to obtain a pass.

## Outputs

Test plan, changed tests, execution report, uncovered risks, and evidence.
